# Практика 3 — Реактивность и Composition API


```bash
npm install
npm run dev
```

Quasar напечатает локальный адрес в терминале. Откройте его в браузере. Для production-сборки: `npm run build`.

1. `src/types/todo.ts` — интерфейс TypeScript: из каких полей состоит задача.
2. `src/composables/useLocalStorage.ts` — composable, `ref`, `watch`, JSON и сохранение в браузер.
3. `src/stores/todoStore.ts` — Pinia store: состояние и действия над задачами.
4. `src/composables/useTodoFilter.ts` — `computed`, поиск и фильтр как производные данные.
5. `src/components/TodoItem.vue` — props и emits: компонент получает задачу и отправляет события.
6. `src/pages/IndexPage.vue` — связывает интерфейс со store и composable; бизнес-логика не реализована прямо в шаблоне.
7. `transition-group` в `IndexPage.vue` — анимация добавления/удаления элементов.

## Теория 

- **Composition API** — способ организовывать логику компонента через функции (`ref`, `computed`, `watch`, composables).
- **`ref`** — реактивное значение. Для доступа из TypeScript используется `.value`; в шаблоне Vue разворачивает ref автоматически.
- **`computed`** — вычисляемое значение, которое обновляется, когда меняются его зависимости. Фильтр не хранит отдельную копию задач.
- **`watch`** — наблюдает за изменением значения и выполняет побочное действие. Здесь он записывает состояние в `localStorage`.
- **Composable** — обычная функция с повторно используемой реактивной логикой. Имена обычно начинаются с `use`.
- **Pinia store** — единое место для состояния приложения и действий над ним.
- **`localStorage`** — браузерное хранилище строк, которое переживает перезагрузку вкладки. Поэтому объекты сериализуются через `JSON.stringify` и читаются через `JSON.parse`.
- **Props / emits** — способ передать данные дочернему компоненту и отправить событие обратно родителю.
- **`transition-group`** — Vue-механизм анимации списка; здесь он анимирует добавление, удаление и перестановку задач.
